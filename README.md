# TapLess

Голосовой ввод для macOS: говорите вместо того, чтобы печатать, и сразу получаете аккуратный текст в нужном окне.

Обычная диктовка пишет «как услышала»: без пунктуации, со словами-паразитами, с «клауд код» вместо Claude Code. TapLess распознаёт речь локально (Whisper), готовит несколько вариантов текста (вычищенная расшифровка, деловое сообщение, свои) с учётом вашего словаря терминов и вставляет выбранный туда, где вы печатали. По умолчанию всё работает на вашем Mac: варианты пишет локальная модель Gemma в [Ollama](https://ollama.com). Вместо неё можно подключить Claude Code или Codex: им TapLess передаёт только свой промпт и текст, без ваших инструкций, навыков и инструментов. У Codex это проверяется пробным запросом на локальный сервер при запуске и после обновления Codex (итог — в меню TapLess).

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/aaudin90/Tapless/main/scripts/install.sh | bash
```

Нужны Mac на Apple Silicon с macOS 14+ (лучше 16 ГБ памяти), [Ollama](https://ollama.com/download/mac) и ~8 ГБ на диске под модели. Модели TapLess скачает сам.

Обновления TapLess проверяет сам, начиная с версии 0.8.0: при запуске и раз в сутки он смотрит последний релиз на GitHub. Если вышла новая версия, появится сообщение и пункт меню «Обновить TapLess до …». После подтверждения TapLess скачает архив, сверит SHA-256 и сертификат подписи и перезапустится уже новой версией. Проверить вручную — меню → «Проверить обновления». Выключить фоновую проверку — `check_updates = false` в `[general]`. Та же команда установки тоже обновляет TapLess.

При первом запуске разрешите доступ к микрофону и включите TapLess в Системные настройки → Конфиденциальность и безопасность → Универсальный доступ. Без второго разрешения текст только копируется в буфер обмена.

## Как пользоваться

1. Нажмите `⌥Э` (`⌥'` в английской раскладке) и говорите.
2. Нажмите `⌥Э` ещё раз. Появится окно с вариантами.
3. Нажмите цифру — текст вставится в окно, где вы были.

```
   ┌──────────────────────────────────────────────────────────────┐
   │ ● Выберите вариант                                         × │
   │ 1  КАК РАСПОЗНАНО   ну вот короче надо глянуть почему кубер… │
   │ 2  КАК СКАЗАЛ       Надо глянуть, почему Kubernetes падает…  │
   │ 3  ДЕЛОВОЕ СООБЩ…   Kubernetes падает при деплое. Прошу …    │
   └──────────────────────────────────────────────────────────────┘
```

`1` — текст как распознан, `2`…`9` — варианты, `⇧` + цифра — только скопировать, `Esc` — закрыть, `⌥Ж` (`⌥;`) — открыть последние варианты снова.

Длинный текст в строке обрезан до `max_lines` строк (`[ui]`). Кнопка ⌄ справа от строки разворачивает его целиком, ⌃ — сворачивает обратно; очень длинный текст прокручивается внутри строки. Вставляется всегда полный текст.

Вариант почти подходит? Нажмите ✎ справа от строки или `⌥` + цифра. Под строкой откроется поле для замечаний, например «короче» или «без списка». Замечания можно ввести руками или надиктовать: `⌥Э` — начать и закончить запись. Надиктованное замечание ИИ сначала вычищает (термины по словарю, пунктуация) той же моделью, что делала строку, и только потом вставляет в поле; выключается пустым `feedback_prompt` в `[llm]`. `↩` — отправить, `⇧↩` — новая строка, `Esc` — отмена. ИИ перепишет строку по замечаниям, новый текст встанет на её место с пометкой «· правка». Править можно несколько раз подряд. Правка не понравилась — нажмите ↶ у строки или `⌥⇧` + цифра: вернётся текст до правки, повторное нажатие откатывает ещё на шаг, до исходного варианта. Текст и шаблон правки — ключи `revise_prompt` и `revise_template` в `[llm]`.

### Bluetooth-наушники и выбор микрофона

Запись с микрофона гарнитуры (AirPods и т. п.) переводит её в профиль HFP: звук у всех программ становится глухим. Поэтому, если микрофон по умолчанию — Bluetooth-гарнитура, TapLess берёт другой: внешний проводной (USB, Thunderbolt) или встроенный микрофон Mac. Наушники остаются в обычном режиме. Если подходящего микрофона нет (например, крышка закрыта), запись идёт с гарнитуры. Если гарнитуру подключили посреди записи, запись продолжается на выбранном микрофоне.

Выбрать микрофон вручную — меню TapLess → «Микрофон»: «Авто» (описано выше), «Как в системе» (всегда микрофон по умолчанию из macOS) или конкретное устройство. Выбор действует со следующей записи и сохраняется в ключ `microphone` секции `[general]`.

Голосовая обработка на звонке. Пока звонилка держит голосовую обработку, встроенный микрофон отдаёт TapLess очень тихий сигнал из трёх каналов, и TapLess усиливает его вручную. Пункт меню «Голосовая обработка на звонке» (ключ `voice_processing` в `[general]`, по умолчанию `"call"`, выключить — `"off"`) включает вместо этого обработку Apple: шумоподавление и автоусиление. Работает только на встроенном микрофоне Mac, когда у него не меньше трёх каналов, то есть во время звонка. USB-микрофоны, звуковые карты и виртуальные устройства (BlackHole) не затрагиваются, даже если у них несколько каналов. Действует со следующей записи, старт записи на звонке дольше (~0,8 с). Если запись во время звонка стала хуже, выключите пункт. Если обработка не запустилась, TapLess напишет предупреждение в лог и до перезапуска (или пока вы не переключите пункт меню) будет записывать звонок с ручным усилением.

### Автовставка без выбора

Если почти всегда нужен один вариант, выберите его в меню TapLess → «Автовставка» (галочка на строке, «Выключена» — обычный выбор цифрой). Выбор действует со следующей диктовки, без перезапуска, и сохраняется в конфиг ключом `auto_select`:

```toml
[paste]
auto_select = 2   # всегда вставлять вариант 2 («Как сказал»)
```

Номер — это цифра строки в панели. При `ui.show_raw = true` `1` — сырой текст, варианты идут с `2`; при `false` — с `1`. После распознавания TapLess запускает только этот вариант, остальные не тратят токены и не грузят Mac. Панель показывает ход работы: «Вставлю автоматически: …». Когда текст готов, он вставляется и панель закрывается. При `auto_select` на сырой текст ИИ не вызывается вообще. Пока вариант не готов, другая цифра меняет выбор (`1` — сразу вставить сырой текст), `⇧` + цифра — только скопировать, `Esc` — закрыть без вставки. Если вариант не удался, панель остаётся с ошибкой: вставьте сырой текст или поправьте строку (`⌥` + цифра). `⌥Ж` показывает только то, что запускалось. Выключить — «Выключена» в меню или `auto_select = 0` (по умолчанию). Неверный номер в конфиге — замечание при запуске, автовставка выключена.

### История диктовок

TapLess сохраняет каждую диктовку в `~/.cache/tapless/history/` (меню → «Папка истории»): аудиозапись (WAV), расшифровку Whisper, все запросы к ИИ с промптом, моделью и ответом, и какой вариант вы вставили. По ней удобно разбирать, где ошибается распознавание или промпт, и пополнять словарь. История хранится 30 дней и не больше 2 ГБ, старое удаляется при запуске и после каждой вставки. Всё лежит на диске **в открытом виде**. Выключить — `enabled = false` в секции `[history]`; там же срок (`retention_days`), предел (`max_size_mb`) и сохранение аудио (`save_audio`).

## Настройка

Настройки — в `~/.config/tapless.toml` (меню → «Открыть конфиг…»). Проще всего попросить ИИ-агента (Claude Code, Codex и др.): для него есть инструкция [`skills/tapless-config/SKILL.md`](skills/tapless-config/SKILL.md). Скопируйте агенту:

```text
Прочитай https://raw.githubusercontent.com/aaudin90/Tapless/main/skills/tapless-config/SKILL.md и по этой инструкции настрой мой TapLess: <что поменять>.
```

Например: «добавь вариант с переводом на английский», «переключи варианты на Claude Code» или «на Codex», «поменяй клавишу записи», «посмотри мои диалоги с агентами и дополни словарь».

Вручную: пишите в файл только то, что меняете; все ключи с комментариями — в [`config.default.toml`](config.default.toml). Правка применяется после меню → «Перезапустить (применить конфиг)».

Если что-то не работает, смотрите меню TapLess (строки «⚠︎ …») и лог: меню → «Открыть лог».

### Какую модель выбрать

Замер на 30 настоящих диктовках трёх размеров, по 10 в группе:

- короткие — 13–30 слов, 8–19 с речи;
- средние — 45–104 слова, 21–64 с;
- длинные — 200–316 слов, 2–3 мин; это несколько диктовок подряд, склеенных в одну.

Каждую диктовку оформляли два варианта по умолчанию, «Как сказал» и «Деловое сообщение», с промптами и словарём TapLess. Всего 60 ответов на модель. Ответы вслепую оценивали два судьи с высоким рассуждением: Claude Opus и Codex `gpt-6.1-sol`. Критическая ошибка — искажён смысл, факт, число, отрицание или термин, потеряна часть текста, ответ не пришёл за 60 с.

| Harness и модель | С критической ошибкой, судья Opus / Sol | Без правок, Opus / Sol | Ответ, медиана / p95 |
|---|---|---|---|
| `claude`, `opus` | 0 % / 28 % | 52 % / 33 % | 5,0 / 10,1 с |
| `codex`, `gpt-6.1-sol`, рассуждение `low` | 5 % / 20 % | 40 % / 55 % | 9,8 / 17,5 с |
| `claude`, `sonnet` | 2 % / 33 % | 27 % / 17 % | 5,1 / 9,5 с |
| `codex`, `gpt-6-luna` (по умолчанию для `codex`) | 28 % / 53 % | 22 % / 15 % | 5,8 / 10,3 с |
| `claude`, `haiku` (по умолчанию для `claude`) | 47 % / 65 % | 10 % / 8 % | 4,7 / 8,8 с |

Доля ответов с критической ошибкой по размеру диктовки (судья Opus / судья Sol):

| Модель | Короткие | Средние | Длинные |
|---|---|---|---|
| `opus` | 0 / 5 % | 0 / 15 % | 0 / 65 % |
| `gpt-6.1-sol` | 5 / 10 % | 10 / 20 % | 0 / 30 % |
| `sonnet` | 0 / 0 % | 5 / 25 % | 0 / 75 % |
| `gpt-6-luna` | 5 / 10 % | 35 / 65 % | 45 / 85 % |
| `haiku` | 35 / 35 % | 45 / 65 % | 60 / 95 % |

Sol судит строже: всё, что Opus счёл критическим, Sol тоже счёл критическим. Ещё Sol считает критическими смену модальности («попробую поднять» → «подниму»), поручение вместо разрешения («можешь закрыть» → «закрой») и неисправленные ошибки распознавания. Чаще всего такие ошибки — в длинных диктовках. Каждый судья ставит свою модель на первое место. Opus и Sol точнее остальных при любом судье. Opus отвечает вдвое быстрее Sol. Sonnet чуть уступает Opus, а Haiku и Luna на средних и длинных диктовках часто искажают смысл.

По прошлому замеру (105 диктовок по 30–150 слов, судья Opus) локальная Gemma `gemma4:e4b-it-q4_K_M` (по умолчанию) ошибается в 44 % ответов, зато отвечает за 1,5 с, работает без интернета и не отправляет текст с вашего Mac.

Включить Opus для всех вариантов:

```toml
[llm]
harness = "claude"

[harness.claude]
model = "opus"
```

Модель можно задать и одному варианту: `[variants.<номер>] model = "opus"`.

Пресет `claude` запускает Claude с `--effort low`. Без флага уровень берётся из `effortLevel` в `~/.claude/settings.json`. На тех же 60 ответах, вперемешку, `low` сравнили с `effortLevel = "high"`:

| Модель | Медиана, `low` / `high` | Длинные диктовки, медиана | Ответов с рассуждением |
|---|---|---|---|
| `opus` | 3,8 / 5,4 с | 6,7 / 10,5 с | 10 / 59 из 60 |
| `sonnet` | 4,7 / 5,0 с | 6,5 / 9,3 с | 6 / 21 из 60 |

Точность с `high` не замерена. Поднять уровень можно так: скопируйте `args` пресета из [`config.default.toml`](config.default.toml) в свой `[harness.claude]` и замените `low` на `high`.

Оговорки:

- каждая диктовка прогнана один раз;
- длинные диктовки склеены из нескольких подряд, поэтому переходы между ними резче, чем в одной речи;
- Claude в замере запускался с `--effort low`, как и пресет `claude` (в версии 0.8.0 и раньше пресет брал уровень из `effortLevel` в `~/.claude/settings.json`);
- облачные модели замерены в разное время, их скорость зависит от нагрузки сервиса.

## Сборка из исходников

```bash
./build_app.sh --install
```

Нужны Xcode 16 или Command Line Tools со Swift 6. Чтобы разрешения не сбрасывались после каждой пересборки, создайте в «Связке ключей» сертификат подписи кода `TapLess Dev`. Подробности — в [`CLAUDE.md`](CLAUDE.md).
