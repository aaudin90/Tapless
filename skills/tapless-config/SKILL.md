# Настройка TapLess

TapLess — голосовой ввод для macOS в меню-баре. Пользователь жмёт горячую клавишу и говорит. Whisper локально превращает речь в текст. Затем текст параллельно уходит в несколько **вариантов** оформления: каждый вариант — запрос к LLM со своим промптом. Во всплывающей панели пользователь жмёт цифру, и TapLess вставляет выбранный текст в активное окно.

Всё поведение задаёт один файл — `~/.config/tapless.toml`. Этот документ объясняет агенту, как его читать и менять.

Источник правды о ключах и значениях по умолчанию — [`config.default.toml`](https://github.com/aaudin90/Tapless/blob/main/config.default.toml) (сырой файл: `https://raw.githubusercontent.com/aaudin90/Tapless/main/config.default.toml`). Если этот документ и `config.default.toml` расходятся, верь `config.default.toml`. Описание для людей — [README](https://github.com/aaudin90/Tapless#readme).

```
⌥Э ─► запись ─► Whisper (stt.initial_prompt) ─► текст
                                                 │
            ┌────────────────────────────────────┼──────────────────────┐
            ▼                                    ▼                      ▼
   клавиша 1: «Как распознано»       [variants.1] → LLM       [variants.2] → LLM …
   (сырой текст, ui.show_raw)         системный промпт = llm.base_prompt
                                      со словарём ({dictionary}) + prompt варианта
                                      harness = [harness.<имя>]: Ollama или CLI
```

## Где что лежит

| Что | Путь |
|---|---|
| Конфиг пользователя | `~/.config/tapless.toml` (или путь из переменной окружения `TAPLESS_CONFIG`) |
| Значения по умолчанию | встроены в приложение; копия с комментариями — `config.default.toml` в репозитории |
| Приложение | `~/Applications/TapLess.app` (или `/Applications/TapLess.app`) |
| Лог | `~/Library/Logs/TapLess/TapLess.log` |
| Промпты последнего запуска вариантов | `~/Library/Application Support/TapLess/run/prompt-<клавиша>.txt` |
| Модели Whisper | `~/Library/Application Support/TapLess/models` |
| История диктовок (`[history]`) | `~/.cache/tapless/history/<дата>/<время>_<сессия>/`: `session.json`, `audio.wav`, `transcript.txt`, `llm/*.txt`; системные промпты — `~/.cache/tapless/prompts/<id>.txt` |

Версия приложения: `defaults read ~/Applications/TapLess.app/Contents/Info CFBundleShortVersionString`. Этот документ описывает TapLess 0.2.0 и новее.

## Правила для агента

1. **Сначала прочитай** `~/.config/tapless.toml` и `config.default.toml`. Не предлагай ключи, которых нет в `config.default.toml`.
2. **Перед правкой сделай копию:** `cp ~/.config/tapless.toml ~/.config/tapless.toml.bak-$(date +%Y%m%d-%H%M%S)`. Скажи пользователю путь копии.
3. **Покажи пользователю, что изменишь** (фрагмент TOML или diff), и правь только после его согласия. Если пользователь заранее разрешил правку («добавь и примени»), отдельно не спрашивай. Пиши в файл только переопределения: не копируй туда весь `config.default.toml`.
4. **Каждый ключ в TOML задаётся один раз.** Если секция (`[dictionary]`, `[variants.2]` …) или ключ (`notes`) уже есть в файле, правь их на месте. Второй такой же заголовок или ключ — ошибка TOML, и TapLess откатится на значения по умолчанию.
5. **Не печатай секреты.** В `[llm.env]` и `[harness.<имя>.env]` могут лежать API-ключи. Не выводи их значения в ответ и в команды; показывай только имена переменных.
6. **Не перезапускай TapLess без согласия:** перезапуск прерывает запись и закрывает панель.
7. **`log.include_text = true` пишет в лог текст всех диктовок.** Включай его только по явной просьбе пользователя и предложи потом выключить.
8. Не меняй файлы внутри `TapLess.app` и не ставь приложение заново ради настройки: всё настраивается через `~/.config/tapless.toml`.

## Как устроен конфиг

- **Итог = значения по умолчанию + файл пользователя поверх них.** В файле пишут только то, что меняют. Ключ пишут вместе с заголовком его секции (`[general]`, `[llm]` …).
- **Таблицы сливаются по ключам рекурсивно**, в том числе `[variants.<номер>]`, `[harness.<имя>]`, `[harness.<имя>.env]`, `[harness.<имя>.options]`, `[schemas.<имя>]`, `[llm.env]`, `[dictionary.terms]`. Пример: в `[harness.claude]` достаточно одного ключа `executable`, остальные возьмутся из значений по умолчанию.
- **Массивы и строки заменяются целиком.** Если задать `stt.drop_phrases` или `llm.extra_path`, значения по умолчанию в этом ключе не используются: повтори нужные элементы сам.
- **Конфиг читается один раз при запуске.** Правка вступает в силу после перезапуска: меню TapLess → «Перезапустить (применить конфиг)».
- **Ошибки.** Если файл не разбирается как TOML, TapLess работает на значениях по умолчанию и при запуске показывает окно «Ошибка в конфиге TapLess». Неизвестные ключи (опечатки), неверные значения `mode`, `position`, `log.level`, ссылки на несуществующий harness или схему, лишние варианты не ломают запуск: TapLess показывает окно «Замечания к конфигу TapLess» и пишет предупреждения в лог.
- Числа — только десятичные: шестнадцатеричные, восьмеричные, двоичные, `nan` и `inf` не поддерживаются.
- Приложение файл пользователя не перезаписывает. Исключение — меню «Автовставка»: оно меняет только строку `auto_select` в `[paste]` (или дописывает её), остальной файл и комментарии не трогает. Если файла нет, оно создаёт шаблон: закомментированную копию значений по умолчанию.
- Многострочные промпты удобно писать литеральными строками `'''…'''`: в них не нужно экранировать кавычки и `\`.

## Справочник ключей

Ниже — все секции. Значения по умолчанию и полные комментарии — в `config.default.toml`.

### `[general]` — клавиши и запись

| Ключ | Что делает |
|---|---|
| `hotkey` | Клавиша записи. По умолчанию `"option+quote"` (`⌥Э` в русской раскладке). Модификаторы: `cmd`, `ctrl`, `option` (`alt`), `shift`. Клавиши: `a`–`z`, `0`–`9`, `space`, `return`, `tab`, `escape`, `f1`–`f20`, `grave`, `section`, `minus`, `equal`, `comma`, `period`, `slash`, `semicolon`, `quote`, `backslash`. Клавиши физические: сочетание работает в любой раскладке. Не бери `ctrl+space` и `ctrl+option+space`: их перехватывает macOS. |
| `show_last_hotkey` | Открыть панель последнего результата снова. По умолчанию `"option+semicolon"` (`⌥Ж`). `""` выключает. |
| `mode` | `"toggle"` — нажал: запись, нажал ещё раз: стоп. `"hold"` — запись, пока клавиша нажата. |
| `sounds` | Звуки начала и конца записи. |
| `min_recording_ms` | Записи короче игнорируются. |
| `tail_ms` | Сколько ещё писать после «стоп». |
| `max_recording_seconds` | Автостоп записи. |
| `check_updates` | Проверять новый релиз на GitHub при запуске и раз в сутки (по умолчанию `true`). Обновление ставится только после подтверждения в меню. `false` — без фоновой проверки, пункт меню «Проверить обновления» остаётся. |

### `[paste]` — вставка

`auto_paste` (`false` — только копировать в буфер), `restore_clipboard`, `paste_delay_ms`, `restore_delay_ms`.

`auto_select` — автовставка (целое, по умолчанию `0` — выключена). `N` — клавиша строки панели: при `ui.show_raw = true` `1` — сырой текст, варианты идут с `2`; при `false` варианты идут с `1`. После распознавания запускается только вариант `N` (остальные — нет, прогрев Ollama — тоже только для него), готовый текст вставляется сам. Пользователь может менять значение в меню TapLess → «Автовставка» без перезапуска; меню пишет его в этот ключ. `N` — сырой текст: ИИ не вызывается. Пока вариант не готов, другая цифра меняет выбор, `Esc` закрывает без вставки. Неверный `N` (нет строки или вариант выключен) — предупреждение при запуске, автовставка выключена. Не путать с `auto_paste`: тот решает, нажимать ли `⌘V`.

### `[ui]` — панель

Клавиши панели: цифра — вставить строку, `⇧`+цифра — только скопировать, `⌥`+цифра — править строку (замечания можно надиктовать главной клавишей; LLM переделает текст по `llm.revise_template` и `llm.revise_prompt`; надиктованные замечания перед вставкой в поле чистит LLM по `llm.feedback_prompt`, `""` — выключить чистку), `⌥⇧`+цифра — откатить последнюю правку строки (повторно — ещё на шаг, до исходного текста), `Esc` — закрыть.

| Ключ | Что делает |
|---|---|
| `position` | `"top"` или `"center"`. |
| `width` | Ширина панели в точках. |
| `max_lines` | Сколько строк варианта показывать; длиннее — кнопка ⌄ у строки разворачивает текст целиком. Вставляется всегда полный текст. |
| `show_raw` | `true` — клавиша `1` вставляет сырой текст Whisper, варианты идут с `2` (максимум 8). `false` — варианты идут с `1` (максимум 9). |

### `[stt]` — распознавание (Whisper)

| Ключ | Что делает |
|---|---|
| `model` | Модель WhisperKit. По умолчанию `openai_whisper-large-v3-v20240930_turbo` (~1,6 ГБ). Другие — в `config.default.toml`. |
| `model_path` | Папка уже скачанной модели; пусто — скачать. |
| `model_repo` | Репозиторий моделей на Hugging Face. |
| `language` | `"ru"`, `"en"`, … или `"auto"`. |
| `initial_prompt` | Короткая статичная подсказка Whisper. См. «Словарь». |
| `silence_threshold` | Если запись тише (RMS), распознавание не запускается. |
| `drop_phrases` | Массив фраз-«галлюцинаций» Whisper на тишине; вырезаются целиком. Задаёшь — заменяешь весь список по умолчанию. |

### `[llm]` — общее для всех вариантов

| Ключ | Что делает |
|---|---|
| `harness` | Имя секции `[harness.<имя>]` для всех вариантов. По умолчанию `"ollama"`. |
| `model` | Модель по умолчанию для `{model}`, если у harness нет своей `model`. |
| `timeout_seconds` | Таймаут одного варианта. |
| `shell`, `login_shell` | Через какой shell запускать CLI-harness (по умолчанию `/bin/zsh -l`): так работают PATH, функции и алиасы из `~/.zshenv` и `~/.zprofile`. `~/.zshrc` не читается. |
| `extra_path` | Папки в начало PATH (массив). |
| `workdir` | Рабочая папка CLI-harness; пусто — пустая папка TapLess. |
| `input_template` | Как подать текст модели; `{text}` — расшифровка. |
| `strip_code_fences` | Снимать обёртку ```` ``` ```` с ответа. |
| `base_prompt` | Общий системный промпт. `{dictionary}` — место словаря. Промпт варианта дописывается в конец. |
| `revise_template` | Входной текст при правке строки панели: `{text}` — расшифровка, `{previous}` — прежний результат, `{feedback}` — замечания автора. |
| `revise_prompt` | Дописывается в конец системного промпта при правке, после промпта варианта. |
| `feedback_prompt` | Задача для чистки надиктованных замечаний при правке: после Whisper замечание проходит через LLM правимой строки (harness и `model` её варианта, без `prompt` и `schema`; для сырого текста — `llm.harness`) и попадает в поле. Системный промпт = `base_prompt` + это; вход — `input_template`. Пустая строка — без чистки. |
| `[llm.env]` | Переменные окружения для всех harness (свободные ключи). |

### `[harness.<имя>]` — чем оформлять текст

Готовые пресеты: `ollama` (по умолчанию), `claude`, `claude-bare`, `codex`, `opencode`, `llm`. Имя секции свободное: можно добавить свой harness.

Общие ключи:

| Ключ | Что делает |
|---|---|
| `type` | `"process"` — запуск CLI (по умолчанию); `"codex"` — запуск Codex CLI с отдельной папкой `CODEX_HOME` (см. «Переключить все варианты на Codex»); `"ollama"` — HTTP-запрос к серверу Ollama. |
| `model` | Модель этого harness. Важнее `llm.model`; `model` варианта важнее её. |
| `parallel` | Сколько вариантов идёт через harness одновременно, остальные ждут. `0` или нет ключа — без ограничения. У `ollama` по умолчанию `3`; очередь общая на сервер (`url`). |

Ключи `type = "process"` и `type = "codex"`:

| Ключ | Что делает |
|---|---|
| `executable` | Обязателен. Имя в PATH, полный путь или функция shell из `~/.zshenv`. |
| `args` | Аргументы всех запусков. Каждый элемент — один аргумент, без кавычек и экранирования. |
| `text_args` / `schema_args` | Добавляются после `args` без схемы / со схемой варианта. |
| `input` | `"stdin"` или `"arg"` (текст в плейсхолдер `{input}`; тогда `{input}` обязан быть в аргументах). |
| `output` | `"text"` — stdout и есть ответ; `"json"` — ответ в JSON по `output_path`. |
| `output_path`, `schema_output_path` | Пути в JSON: ключи через точку, индексы числами (`"items.0.text"`, `-1` — последний). |
| `[harness.<имя>.env]` | Свои переменные окружения. |
| `verify` | Только `type = "codex"`. Что делать, если проверка изоляции нашла лишнее в запросе: `"warn"` (по умолчанию) — предупредить, `"block"` — не вызывать harness. `AGENTS.md` в запросе блокирует вызовы всегда. |

Плейсхолдеры в `args`, `text_args`, `schema_args`: `{model}`, `{prompt_file}`, `{system_prompt}`, `{input}`, `{schema}`, `{schema_file}`. Программа также получает переменные `TAPLESS_MODEL`, `TAPLESS_PROMPT_FILE`, `TAPLESS_SCHEMA_FILE`, `TAPLESS_VARIANT` (клавиша), `TAPLESS_VARIANT_NAME`.

Ключи `type = "ollama"`: `url` (по умолчанию `http://127.0.0.1:11434`), `think` (`false`, `true` или `"low"`/`"medium"`/`"high"`), `keep_alive` (по умолчанию `"-1"` — модель не выгружается; `"1h"` — выгрузить через час простоя), `[harness.<имя>.options]` (`temperature`, `num_ctx`, `top_p` …). Ключи CLI для Ollama не нужны. Модель по умолчанию — `gemma4:e4b-it-q4_K_M`; тег пиши полностью: голый `gemma4:e4b` на Apple Silicon — другая, тяжёлая сборка. Недостающую модель TapLess скачивает сам при запуске.

### `[schemas.<имя>]` — структурированный ответ

`json` (JSON Schema текстом) или `file` (путь, важнее `json`), `result_path` (какое поле вставлять). Вариант ссылается ключом `schema = "<имя>"`. Нужна редко: обычный текстовый ответ проще.

### `[log]`

`level` — `"debug"`, `"info"`, `"warning"`, `"error"`. `include_text` — писать в лог текст диктовок и ответов (см. правило 7).

### `[history]` — история диктовок (TapLess 0.4.0+)

Каждая диктовка — папка `<dir>/history/<гггг-мм-дд>/<чч-мм-сс>_<первые 8 символов сессии>/`:

- `session.json` — всё структурно: время, приложение-цель, расшифровка, каждый вызов LLM (`purpose`: `variant`, `revision`, `feedback`; клавиша, harness, модель, `prompt_id`, вход, ответ или ошибка, время), выбранная строка (`deliveries`);
- `audio.wav` — запись, `transcript.txt` — расшифровка Whisper;
- `feedback-<N>.wav` / `.txt` — надиктованные замечания к правке;
- `llm/<NN>-<purpose><клавиша>-<модель>-<prompt_id>.txt` — ответ LLM;
- системные промпты лежат отдельно, без повторов: `<dir>/prompts/<prompt_id>.txt`.

| Ключ | Что делает |
|---|---|
| `enabled` | `true` — сохранять. `false` — не сохранять; старое всё равно удаляется по сроку |
| `dir` | Папка; пусто — `~/.cache/tapless` |
| `save_audio` | Сохранять WAV (16 кГц mono, ~1,9 МБ на минуту речи) |
| `retention_days` | Срок хранения в днях; `0` — без срока |
| `max_size_mb` | Предел размера `history/`; при превышении удаляются самые старые диктовки, кроме последней. `0` — без предела |

Чистка — при запуске и после каждой вставки. История хранится в открытом виде: в ней текст диктовок, как в логе с `include_text`.

### `[variants.<номер>]` — варианты оформления

| Ключ | Что делает |
|---|---|
| `name` | Подпись в панели. По умолчанию «Вариант <номер>». |
| `prompt` | Задача варианта; дописывается после `base_prompt`. **Обязателен для нового номера.** |
| `model`, `harness`, `schema` | Необязательно: своя модель, свой harness, своя схема. |
| `enabled` | `false` — временно выключить. |

- Номер — целое число от 1, без нулей впереди. Номер задаёт порядок, но **не клавишу**.
- Клавиши раздаются по порядку среди включённых вариантов: при `show_raw = true` первый включённый вариант — клавиша `2`. Выключил вариант — следующие сдвигаются.
- Ключи из файла заменяют только эти ключи варианта с тем же номером. Новый номер добавляет вариант. **Новому варианту бери свободный номер:** больше всех номеров из `config.default.toml` (там 1 и 2) и из файла пользователя. Занятый номер молча заменит `name` и `prompt` существующего варианта.
- Клавиша варианта = место среди включённых вариантов (по возрастанию номера) + 1 при `show_raw = true`. Пример: включены 1, 2, 3, 5 → клавиши 2, 3, 4, 5.
- По умолчанию вариантов два: `[variants.1]` «Как сказал» (вычищенная расшифровка) и `[variants.2]` «Деловое сообщение».
- Все варианты запускаются одновременно. Для Ollama общая скорость делится между запросами: каждый новый вариант заметно удлиняет ожидание панели.
- Старый формат `[[variants]]` — ошибка конфига.

## Словарь

Словарь помогает правильно писать термины, имена и жаргон. Он работает в двух местах, и у каждого своя роль.

**1. Whisper — `stt.initial_prompt`.** Короткая строка терминов через запятую, например `"Claude Code, Ollama, Kubernetes."`. Whisper видит её как «предыдущий текст» и чаще пишет эти слова верно. Ограничение жёсткое: на окно речи до 30 с у Whisper 224 токена, и подсказка отнимает их у распознанного текста. Длинная подсказка обрывает диктовку. Держи её до ~25 токенов (5–8 терминов, кириллица — 2–3 токена на слово). Длиннее 48 токенов TapLess отбрасывает начало подсказки и пишет предупреждение в лог. Добавляй сюда термин, только если Whisper упорно пишет его неверно и ИИ не спасает.

**2. ИИ — `[dictionary]`.** Это основной словарь. Он идёт в системный промпт каждого варианта на место `{dictionary}`. Других замен нет: TapLess не делает regex- или локальных замен, строка «Как распознано» — чистый вывод Whisper.

```toml
[dictionary]
notes = """
Автор — Android-разработчик, диктует рабочие сообщения про код и CI.
Латинские названия не склоняй: «в Ollama», «через Claude Code».
«ди» в контексте кода — DI; «го» как призыв («го обедать») не трогай.
Жаргон оставляй кириллицей: коммит, мерж, ревью, пайплайн.
"""

[dictionary.terms]
# "как писать" = ["как может прийти из распознавания", …]
"Kubernetes" = ["кубер", "кубернетес"]
"Ollama" = ["оллама", "алама", "Allama"]
"Иван Петров" = []    # просто правильное написание
```

- `[dictionary.terms]` — таблица: ключ — правильное написание, значение — массив ошибочных форм, которые реально приходят из Whisper (кириллицей или странной латиницей). Падежи, регистр и дефисы ИИ узнаёт сам: хватит 1–4 примеров на термин.
- Таблица сливается с терминами по умолчанию по ключам, а массив форм у ключа заменяется целиком. Чтобы дополнить термин по умолчанию (например, `"Claude Code"`), задай тот же ключ и повтори его прежние формы из `config.default.toml`, иначе они пропадут.
- `notes` — одна строка. Новые правила дописывай в существующий текст `notes`, а не вторым ключом.
- В промпте ИИ видит строки вида `Kubernetes ← кубер, кубернетес` и абзац `notes`.
- `notes` — свободный текст: кто диктует, о чём, правила написания. Короткие обычные слова («го», «ди», «мр»), которые бывают и термином, и простым словом, описывай в `notes` с условием, когда менять. Если положить их в `terms`, ИИ начнёт менять их везде.
- Жаргон, который автор пишет кириллицей (коммит, мерж), впиши в `notes`, чтобы ИИ не переводил его в латиницу.
- Словарь длиной в десятки терминов — норма для ИИ: он занимает сотни токенов промпта, это быстро. Но не копи сотни строк: каждая строка удлиняет каждый запрос.

## Проверка после правки

1. Синтаксис TOML:

   ```bash
   python3 -c "import tomllib,os;tomllib.load(open(os.path.expanduser('~/.config/tapless.toml'),'rb'));print('ok')"
   ```

2. Ключи: каждый новый ключ и секция должны быть в `config.default.toml` (кроме свободных таблиц: `[llm.env]`, `[harness.<имя>.env]`, `[harness.<имя>.options]`, `[dictionary.terms]`, новых `[variants.<номер>]`, `[harness.<имя>]`, `[schemas.<имя>]`).
3. С согласия пользователя перезапусти TapLess. Пользователь может сделать это сам: меню TapLess → «Перезапустить (применить конфиг)». Из терминала:

   ```bash
   pkill -x TapLess; while pgrep -x TapLess >/dev/null; do sleep 0.2; done; open -a TapLess
   ```

4. Проверь лог запуска: замечания к конфигу и итоговые варианты.

   ```bash
   grep -E "\[config\]" ~/Library/Logs/TapLess/TapLess.log | tail -40
   ```

   Строки `WARNING [config]` и `ERROR [config]` — замечания и ошибки. Строки `Конфиг: вариант <клавиша> «Имя» model=…, harness=…` показывают, что получилось после слияния.
5. Попроси пользователя надиктовать фразу с новыми терминами и проверить панель. Из агента микрофон и панель не проверить.

## Примеры использования

### Пополнить словарь по истории диалогов с агентами

Если пользователь диктует сообщения агентам, их история — лучший источник ошибок распознавания. Пользователь говорит «Посмотри мои диалоги и дополни словарь TapLess».

1. **Уточни источники и период**, если пользователь их не назвал. История — личные данные: читай её только с согласия, в ответ выводи только найденные термины и формы, не целые сообщения. Выборку держи во временной папке пользователя (`$TMPDIR`) и удали её в конце.
2. **Найди сообщения пользователя.** Возможные места (проверь, что есть на машине):

   | Агент | Где сообщения пользователя |
   |---|---|
   | Claude Code | `~/.claude/history.jsonl` (поле `display`, есть `project`); полные сессии — `~/.claude/projects/<проект>/*.jsonl`, строки с `"type":"user"`, текст — `message.content`, если это строка |
   | Codex | `~/.codex/history.jsonl` (поле `text`); сессии — `~/.codex/sessions/<год>/<месяц>/<день>/rollout-*.jsonl`; диктовка приложения Codex — `~/.codex/transcription-history.jsonl` |
   | OpenCode | `~/.local/share/opencode/` (`storage/`, `opencode.db` — SQLite) |
   | TapLess | история `~/.cache/tapless/history/*/*/session.json`: `stt.text` (как распознал Whisper) рядом с `deliveries[].text` (что пользователь вставил) — лучший источник пар «ошибка → термин»; иначе лог `~/Library/Logs/TapLess/TapLess.log`, строки «Распознавание завершено …», только если включён `log.include_text` (правило 7) |

   Выборка последних 500 сообщений Claude Code, без слэш-команд и вставок, по одному сообщению на строку:

   ```bash
   python3 -c "import json,os;L=[json.loads(l).get('display','') for l in open(os.path.expanduser('~/.claude/history.jsonl'))];[print(t.replace('\n',' ')) for t in L[-500:] if t and not t.startswith('/') and '[Pasted text' not in t]" > "$TMPDIR/tapless-msgs.txt"
   ```

   Добавить Codex (история и диктовка, по 500 последних строк, если файлы есть):

   ```bash
   python3 -c "import json,os;P=[os.path.expanduser(f) for f in ('~/.codex/history.jsonl','~/.codex/transcription-history.jsonl')];[print(json.loads(l).get('text','').replace('\n',' ')) for p in P if os.path.exists(p) for l in open(p).readlines()[-500:]]" >> "$TMPDIR/tapless-msgs.txt"
   ```

3. **Найди кандидатов.** Скрипт ниже считает латинские слова, которых нет в `[dictionary.terms]` пользователя, и показывает короткий контекст. Сохрани его в `$TMPDIR/tapless-mine.py` и запусти `python3 "$TMPDIR/tapless-mine.py" "$TMPDIR/tapless-msgs.txt"`:

   ```python
   import collections, os, re, sys, tomllib
   cfg = tomllib.load(open(os.path.expanduser("~/.config/tapless.toml"), "rb"))
   known = set()
   for term, forms in cfg.get("dictionary", {}).get("terms", {}).items():
       known.update(w.lower() for w in re.findall(r"\w+", " ".join([term, *forms])))
   count, ctx = collections.Counter(), {}
   for line in open(sys.argv[1], encoding="utf-8"):
       cyr, lat = len(re.findall(r"[А-Яа-яЁё]", line)), len(re.findall(r"[A-Za-z]", line))
       if cyr <= lat:  # логи, код и английские вставки — не диктовка
           continue
       for m in re.finditer(r"\b[A-Za-z][A-Za-z0-9.\-]{2,}\b", line):
           word = m.group().lower()
           if word in known:
               continue
           count[word] += 1
           ctx.setdefault(word, line[max(0, m.start() - 35):m.end() + 35].strip())
   for word, n in count.most_common(80):
       print(f"{n:4} {word:20} …{ctx[word]}…")
   ```

   В списке будут и верно написанные слова (`OpenAI`, `GraphQL`): кандидат — то, что похоже на искажённое название. Кириллические ошибки («кубер», «клауд код») скрипт не ищет: просмотри выборку глазами или поищи `grep -io` по известным корням. Признаки надиктованного текста с ошибкой:
   - англоязычные термины, записанные кириллицей: «кубер», «даггер», «градл», «клауд код»;
   - странная латиница на месте русского или известного слова: «Allamus», «LinkFuse», «Tables» вместо TapLess;
   - одно и то же название в разных написаниях;
   - слова, которые пользователь потом исправлял в следующем сообщении («не клауд, а Claude»).

   Названия проектов, сервисов, коллег и библиотек из рабочих диалогов — тоже кандидаты.
4. **Сверь с текущим словарём.** Не дублируй термины из `[dictionary.terms]` пользователя и из значений по умолчанию; к существующим добавь новые ошибочные формы.
5. **Предложи таблицу:** термин → ошибочные формы → откуда взято → куда добавить (`terms` или `notes`). Слова, которые бывают обычными словами, — в `notes` с условием. Жаргон, который пользователь пишет кириллицей, — в `notes`, в список «оставляй кириллицей».
6. **После согласия** допиши строки в `[dictionary.terms]` и `notes` (правила 2–4), проверь файл и предложи перезапуск. В `stt.initial_prompt` добавляй 1–3 самых частых термина, только если их там нет и бюджет ~25 токенов позволяет.
7. **Удали выборку:** `rm -f "$TMPDIR/tapless-msgs.txt" "$TMPDIR/tapless-mine.py"`.

### Добавить вариант

«Добавь вариант с переводом на английский». Сначала найди свободный номер (см. «Варианты»). Если в файле пользователя вариантов нет, свободен `3`:

```toml
[variants.3]
name = "English"
prompt = '''
Translate into natural, fluent English. Keep the meaning, tone and formatting.'''
```

Скажи пользователю клавишу нового варианта: с двумя вариантами по умолчанию и `show_raw = true` это `4`. Предупреди, что каждый параллельный вариант удлиняет ожидание панели, если варианты идут через Ollama; сверх `parallel` (по умолчанию 3) варианты ждут очереди.

### Поменять промпт или выключить вариант

```toml
[variants.2]
prompt = '''Перепиши как короткое сообщение для Telegram, без канцелярита.'''

[variants.1]
enabled = false
```

### Переключить все варианты на Claude Code

```toml
[llm]
harness = "claude"
model = "haiku"
```

`haiku` — быстрая, но ошибается чаще. Точнее и почти не медленнее — `opus` и `sonnet`: по замеру TapLess (судья Opus) критических ошибок у `opus` 0 %, у `sonnet` 2 %, у `haiku` 47 % (таблица — в README, «Какую модель выбрать»). Для них задай `model = "opus"` или `model = "sonnet"`.

Команда `claude` должна работать в Терминале. Пресет запускает `claude -p --safe-mode` с промптом TapLess вместо промпта Claude Code и без инструментов: `~/.claude/CLAUDE.md`, навыки, плагины, хуки и MCP пользователя в запрос не попадают, `language` из `~/.claude/settings.json` снят (`--settings '{"language":""}'`). Если `claude` запускается обёрткой (функция в `~/.zshenv`), переопредели только программу:

```toml
[harness.claude]
executable = "my-claude-wrapper"
```

Проверить такой harness без GUI:

```bash
echo '<transcript>ну вот короче надо проверить клауд код</transcript>' | zsh -l -c '"$0" "$@"' claude -p --safe-mode --settings '{"language":""}' --model haiku --tools "" --output-format text
```

### Переключить все варианты на Codex

```toml
[llm]
harness = "codex"
```

Команда `codex` должна работать в Терминале, вход в Codex — выполнен (`codex login`). Модель по умолчанию — `gpt-6-luna` (`model` в `[harness.codex]`), рассуждение выключено (`model_reasoning_effort="none"` в `args`). Если `codex` запускается обёрткой (функция в `~/.zshenv`), переопредели только программу:

```toml
[harness.codex]
executable = "my-codex-wrapper"
```

Чем `type = "codex"` отличается от обычного CLI:

- TapLess запускает Codex с отдельной папкой `CODEX_HOME` — `~/Library/Application Support/TapLess/codex-home`. Иначе Codex добавил бы к промпту `~/.codex/AGENTS.md` пользователя, загрузил MCP-серверы, навыки и память.
- В эту папку TapLess переносит из `~/.codex` только вход (`auth.json` — символическая ссылка) и провайдера: `model_provider`, `[model_providers.*]`, `openai_base_url`, `chatgpt_base_url`, `forced_login_method`, `forced_chatgpt_workspace_id`, `cli_auth_credentials_store`. Все инструменты, веб-поиск и телеметрию TapLess выключает: модель получает пустой список инструментов. Инструменты из профиля модели убирает свой каталог моделей `model-catalog.json` — копия `models_cache.json` Codex без них; если кэша моделей нет, TapLess берёт встроенный каталог (`codex debug models --bundled`). Папка пересобирается при изменении `~/.codex/config.toml`; править её руками бесполезно.
- Другой источник входа и провайдера — `CODEX_HOME` в `[harness.codex.env]`.
- Вход в связке ключей (`cli_auth_credentials_store = "keyring"`) так не работает: нужен `auth.json` или `CODEX_API_KEY` в `[harness.codex.env]`.
- Системный промпт TapLess (`base_prompt` со словарём + промпт варианта) заменяет встроенный промпт Codex через `-c model_instructions_file="{prompt_file}"`.
- Если модель не принимает `model_reasoning_effort="none"`, замени `args` целиком, со значением `"low"`. Так нужно для `gpt-6.1-sol`: по замеру TapLess он точнее `gpt-6-luna` (критических ошибок 14 % против 27 %), но медленнее (медиана 9,2 с против 7,0 с).
- Проверка изоляции. При запуске TapLess, раз в сутки перед вызовом и после пересборки папки TapLess сверяет версию Codex, каталог моделей, конфиг и `args`. Если что-то изменилось, Codex с этими `args` отправляет пробный запрос на локальный сервер TapLess (до провайдера он не доходит, токены не тратятся). TapLess проверяет, что в запросе только его промпт и текст: без инструментов, навыков, `AGENTS.md`, с той же моделью и `model_reasoning_effort`. Итог — в меню TapLess (строка «Codex …», пункт «Проверить Codex снова») и в логе; прошлые итоги — `~/Library/Application Support/TapLess/codex-check.json`. Если проверка нашла лишнее после правки `args`, верни флаги из `config.default.toml`.

Проверить Codex без GUI (в пустой папке, без `AGENTS.md`):

```bash
cd "$(mktemp -d)" && echo '<transcript>ну вот короче проверка связи</transcript>' | CODEX_HOME="$HOME/Library/Application Support/TapLess/codex-home" zsh -l -c '"$0" "$@"' codex exec --ephemeral --skip-git-repo-check --sandbox read-only --model gpt-6-luna -c 'model_reasoning_effort="none"' -
```

Папка `codex-home` появляется после первого варианта через Codex. Пока её нет, проверяй без `CODEX_HOME=…`; тогда Codex подмешает `~/.codex/AGENTS.md`.

### Сменить модель Ollama или параллельность

```toml
[harness.ollama]
model = "gemma4:e4b-it-qat"
parallel = 2
```

TapLess сам скачает модель при запуске. Если сервер Ollama уже запущен не TapLess-ом, его `OLLAMA_NUM_PARALLEL` должен быть не меньше `parallel`.

### Всегда вставлять один вариант

```toml
[paste]
auto_select = 2   # строка 2 панели: по умолчанию «Как сказал»
```

Номер — цифра строки в панели, а не номер секции `[variants.<номер>]`: включённые варианты получают клавиши по порядку. При `ui.show_raw = true` `1` — сырой текст, первый включённый вариант — `2`, второй — `3`; при `false` первый включённый вариант — `1`. Выключенные (`enabled = false`) клавиш не получают и сдвигают следующие. Отключить — `auto_select = 0`. После правки файла перезапусти TapLess; проще — выбрать строку в меню TapLess → «Автовставка», это применяется сразу.

### Поменять клавиши

```toml
[general]

```

### Разобрать ошибку варианта

1. `grep -E "WARNING|ERROR" ~/Library/Logs/TapLess/TapLess.log | tail -20`.
2. «Программа … не найдена» — добавь папку программы (`which <программа>`) в `llm.extra_path` или перенеси функцию shell в `~/.zshenv`.
3. «Ollama: …» — проверь сервер: `curl -s http://127.0.0.1:11434/api/version`, затем меню → «Проверить Ollama снова».
4. Таймаут — увеличь `llm.timeout_seconds` или уменьши число вариантов.
